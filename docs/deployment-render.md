# SecureLeaf — Deploying on free tiers (Render + Vercel + Neon + Upstash + Backblaze + Brevo)

> For a **small beta (~5 users) at ₹0, with no credit card anywhere**. The main production plan
> is still one Oracle server ([`deployment.md`](deployment.md)); this replaces its "Plan B" appendix
> with something that was actually measured. Why each limit below exists:
> [`learning-notes/perf-01-purchase-time-watermarking.md`](learning-notes/perf-01-purchase-time-watermarking.md).

```
Browser ──► Vercel (React app, static)            free, never sleeps
   │
   └──────► Render (Spring Boot, Docker)          free: 512 MB, 0.1 CPU, sleeps after 15 min idle
               ├─► Neon        Postgres (TLS)     free: 0.5 GB
               ├─► Upstash     Redis (TLS)        free: 256 MB, 500k commands/month
               ├─► Backblaze B2 files (S3 API)    free: 10 GB
               └─► Brevo       email (HTTPS API)  free: ~300 emails/day
```

## What to expect (measured under 512 MB / 0.1 CPU)

| | |
|---|---|
| Startup after a deploy or restart | **~14 minutes** (the site is down meanwhile) |
| Reading a page, 5 people reading at once | median **~5 s**, p95 ~20 s (no prefetch in the test; the real reader prefetches the next page while you read) |
| A buyer's pages after purchase | generated in the background, ~2–3 min per 12-page book; until then pages are watermarked live (slower) |
| Processing an upload | ~16 s per page (~3 min for 12 pages) |

Deploy deliberately (`autoDeploy: false`), at quiet hours.

## 1. Create the managed services (all free, no card)

Pick **Singapore / ap-southeast-1** wherever a region is offered (nearest to India and to Render's
Singapore region).

1. **Neon** (neon.tech): new project, region *AWS Asia Pacific (Singapore)*. From the connection
   details note **host**, **database**, **user**, **password** → `DB_HOST`, `DB_NAME`, `DB_USER`,
   `DB_PASSWORD`. (The render profile adds `sslmode=require`.)
2. **Upstash** (upstash.com): create a Redis database, region *ap-southeast-1*, TLS on. Note
   **endpoint** and **password** → `REDIS_HOST`, `REDIS_PASSWORD` (port 6379).
3. **Backblaze B2** (backblaze.com → B2 Cloud Storage):
   - Create **three private buckets** with names that are unique across all of B2, e.g.
     `secureleaf-<you>-raw`, `secureleaf-<you>-tiles`, `secureleaf-<you>-thumbs`
     → `MINIO_BUCKET_RAWUPLOADS`, `MINIO_BUCKET_TILES`, `MINIO_BUCKET_THUMBNAILS`.
   - The bucket page shows the **S3 endpoint**, e.g. `s3.us-west-004.backblazeb2.com`
     → `MINIO_ENDPOINT=https://s3.us-west-004.backblazeb2.com`, `MINIO_REGION=us-west-004`.
   - *App Keys → Add a New Application Key*, access to **all buckets**, read and write
     → `keyID` = `MINIO_ACCESS_KEY`, `applicationKey` = `MINIO_SECRET_KEY` (shown once).
4. **Brevo** (brevo.com): *Senders & IP* → verify the address you will send from (`MAIL_FROM`);
   *SMTP & API → API Keys* → create one → `BREVO_API_KEY`.
5. **Razorpay (test mode)**: as in [`deployment.md` §0](deployment.md), with the webhook URL
   `https://<your-render-service>.onrender.com/api/webhooks/razorpay`.

## 2. Backend on Render

1. render.com → **New → Blueprint** → connect the GitHub repo; Render reads `render.yaml`.
   Choose the branch to deploy.
2. Fill in every value it asks for (the `sync: false` ones). `JWT_SECRET` and `DRM_SIGNING_SECRET`
   are generated by Render. Leave `FRONTEND_BASE_URL` and `CORS_ALLOWED_ORIGINS` as a placeholder
   (e.g. `https://example.invalid`) until step 3 gives you the Vercel URL.
3. Deploy. Expect ~14 minutes before the log shows `Started SecureLeafApplication`.
4. Check: `curl https://<service>.onrender.com/actuator/health/liveness` → `{"status":"UP"}`, and
   `curl -s -o /dev/null -w '%{http_code}' https://<service>.onrender.com/actuator/prometheus`
   → **not 200** (metrics must not be public; the render profile exposes only `health`).

If the service name `secureleaf-backend` was taken and Render gave you a different URL, update the
`connect-src` entry in `frontend/vercel.json` to match.

## 3. Frontend on Vercel

1. vercel.com → **Add New → Project** → import the repo → **Root Directory: `frontend`**
   (framework preset: Vite).
2. Environment variables (all use the Render URL from step 2):

   | Variable | Value |
   |---|---|
   | `VITE_GRAPHQL_URL` | `https://<service>.onrender.com/graphql` |
   | `VITE_API_URL` | `https://<service>.onrender.com/api` |
   | `VITE_NOTIFICATIONS_STREAM_URL` | `https://<service>.onrender.com/api/notifications/stream` |
   | `VITE_GOOGLE_CLIENT_ID` | optional; empty disables Google sign-in |

3. Deploy, note the URL (e.g. `https://secureleaf.vercel.app`), then go back to Render and set
   `FRONTEND_BASE_URL` and `CORS_ALLOWED_ORIGINS` to it. That needs one more Render deploy.

Vercel's free Hobby plan is for **non-commercial** use: fine while payments are in Razorpay test
mode; move the frontend (e.g. to Cloudflare Pages) before live payments.

## 4. Keep it awake

Render stops a free service after 15 minutes without traffic, and waking it means a full ~14-minute
start. Create a free **UptimeRobot** HTTP monitor on `https://<service>.onrender.com/actuator/health/liveness`
every **5 minutes**. One service running all month uses ~744 of Render's 750 free hours.

## 5. Smoke test

Register → become creator → upload a small PDF (wait for LIVE) → with a second account, buy it
(test card) → open it in the reader. In the Render log, within a minute or two of the purchase:
`Pre-watermarked N page(s) for entitlement …`. Request a password reset and check it arrives (Brevo).

## Free-tier limits to watch

| Service | Limit | What happens at the limit |
|---|---|---|
| Render | 750 instance-hours/month, 512 MB | service suspended until next month / OOM restart |
| Neon | 0.5 GB storage | writes fail |
| Upstash | 500k commands/month | Redis refuses; the rate limiter fails open, sessions fail |
| Backblaze B2 | 10 GB storage; daily download and transaction caps | requests blocked until the next day |
| Brevo | ~300 emails/day | sends fail; counted in `secureleaf.mail.send.failures`, the business flow is unaffected |

No card is on file anywhere, so hitting a limit stops a service; it cannot create a bill.
